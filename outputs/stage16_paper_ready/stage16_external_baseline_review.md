# Stage16 external scoring baseline review

Scope: ranking the same six frozen Stage15B candidate trajectories. No external baseline has been fitted or compared numerically in this stage. Two **scoring-component adaptations** pass source-code feasibility; neither is a reproduction of its entire predictor. The existing seven-model experiment remains an internal controlled comparison, not a cross-paper leaderboard comparison.

Search covered mode scoring, confidence estimation, trajectory reranking and interaction-aware ranking, using arXiv, conference proceedings, CrossRef metadata and public repositories. Academic-search MCP is unavailable. Unauthenticated GitHub API returned HTTP 403; commit IDs were obtained by `git ls-remote` and code fetched from pinned raw URLs. Publisher access to the R-RNet full text was blocked by a browser challenge: bibliographic information is verified against CrossRef and publisher DOI, while its detailed scoring implementation is verified against author code. See [code provenance](02_literature/), including hashes and a reproducible no-fit preflight. Search is a focused feasibility screen, not an exhaustive systematic review.

## 1. TNT scoring component — conditional recommendation

[TNT: Target-driveN Trajectory Prediction](https://proceedings.mlr.press/v155/zhao21b.html), Hang Zhao et al., CoRL 2020; proceedings published 2021, PMLR 155. [Paper](https://proceedings.mlr.press/v155/zhao21b/zhao21b.pdf), [arXiv](https://arxiv.org/abs/2008.08294). The method has target prediction, target-conditioned trajectory generation, then trajectory scoring and diversity selection. The scoring distribution is softmax over complete candidate trajectories; its soft targets use maximum squared pointwise trajectory distance to GT. This is distinct from our endpoint-FDE Loss A/C. [Paper scoring definition](https://proceedings.mlr.press/v155/zhao21b/zhao21b.pdf).

[Public implementation](https://github.com/Henry1iu/TNT-Trajectory-Prediction) is explicitly **unofficial**, pinned at `bcbccdc1d35a717793e3caa1d599c1f700612227`. `TrajScoreSelection` takes context `[B,1,C]` and flattened trajectories `[B,M,2T]`, uses a residual MLP with LayerNorm and ReLU plus a scalar linear head, and returns softmax probabilities `[B,M]`. Its loss is `-sum(q*log(p))`, `q=softmax(-max_t ||trajectory_t-GT_t||² / temper)`. The constructor's temperature is 0.01; the actual tensor assertion requires 3D context although its docstring says 2D. [Pinned scoring code](https://github.com/Henry1iu/TNT-Trajectory-Prediction/blob/bcbccdc1d35a717793e3caa1d599c1f700612227/core/model/layers/scoring_and_selection.py), [MLP code](https://github.com/Henry1iu/TNT-Trajectory-Prediction/blob/bcbccdc1d35a717793e3caa1d599c1f700612227/core/model/layers/basic_module.py).

Proposed adaptation, not implemented as a scientific model: set M=6 and T=12, pass fixed HiVT trajectories in a consistent target-centered frame, and use detached **history-only** frozen HiVT context in place of VectorNet context. The caches currently do not expose that latent context, so an instrumentation-only forward/export, with exact-output invariance, is necessary. Preserve the actual TNT scoring network and trajectory-distance soft CE; do not substitute Loss C and call it TNT. This preserves the scoring mechanism but changes its context source, horizon, candidate source/count and joint-training setting. Omit TNT target generation and NMS because removing/replacing candidates violates this fixed-candidate comparison. Name any future result “TNT scoring component adapted to frozen HiVT candidates,” never “TNT reproduction.”

Engineering estimate: three small scorer fits plus history-context export, not three new HiVT fits. At C=64,T=12 the tested component has 16,001 parameters. Approximately 1–4 RTX 3080 GPU hours for three bounded scorer fits plus 0.5–2 hours for forward/context export is an **unmeasured budget estimate**, not a benchmark. Train/selection scenes and normalization must remain InnerTrain/InnerDev; loss temperature must be registered or chosen on InnerDev before Outer evaluation. No such experiment is authorized by this review alone.

## 2. R-RNet probability predictor — technically simpler component adaptation

[R-RNet: Probability-Driven Networks for Pedestrian Trajectory Prediction](https://doi.org/10.1109/TITS.2025.3630200), Mingjun Ma et al., IEEE T-ITS 27(1), 857–867, January **2026** (DOI contains 2025; do not use that alone as publication year). [Publisher record](https://ieeexplore.ieee.org/document/11249798), [CrossRef metadata](https://api.crossref.org/works/10.1109/TITS.2025.3630200), [author repository](https://github.com/RoboSafe-Lab/R-RNet). Its complete system samples goals, scores them, refines goals and produces trajectories; the probability component can be separated for an endpoint-conditioned comparison. [Author workflow](https://github.com/RoboSafe-Lab/R-RNet).

Code pinned at `2edb131d4a5e08365739695fec0a05351fe535f8`: `predict_prob` concatenates observed xy history with each candidate goal, encodes it using a bidirectional GRU (hidden size 32 each direction), then a 64→32→16→1 ReLU/Sigmoid decoder. It returns bounded scores and softmax-normalized scores. The probability loss is `20*mean(abs(score-1/(1+endpoint_distance)))`; it is not CE and the multiplier remains 20 even with six candidates. [Network and scoring function](https://github.com/RoboSafe-Lab/R-RNet/blob/2edb131d4a5e08365739695fec0a05351fe535f8/rrnet/modeling/rrnet.py), [actual loss](https://github.com/RoboSafe-Lab/R-RNet/blob/2edb131d4a5e08365739695fec0a05351fe535f8/rrnet/layers/loss.py).

Proposed adaptation: take the unchanged candidate endpoints, prepend five observed positions in the same target-centered meter frame, and evaluate all K=6 scores. Keep GRU/decoder/loss and score normalization; no new neighbor messages, future GT in input, goal refinement or generation. Handle historical padding explicitly by a frozen rule and train moments only if normalization is adopted. The recurrent scorer supports variable observation length; moving from the original pedestrian protocol to mixed nuScenes types and five history points remains a documented domain adaptation. It discards full-path information, so it is an endpoint-confidence control, not an interaction-aware competitor. Extracting only this module removes most of R-RNet's full method; use the name “R-RNet probability component adaptation.”

The exact extracted component has 9,537 parameters, with finite gradients and `[B,6,1]` probabilities. Its Sigmoid-before-softmax imposes a bounded score range, a relevant difference from unrestricted logits; preserve it rather than silently sharpening probabilities. Engineering estimate: three small fits, no extra predictor forwards because frozen context contains observed history and endpoints; approximately 1–4 GPU hours total, **not measured**. Before implementation, resolve licensing (no LICENSE file is present in the pinned repository tree) and register coordinate/padding conventions. Publicly readable code alone is not a redistribution license.

## Screened out

- [PRANK, NeurIPS 2020](https://papers.nips.cc/paper/2020/hash/1b0251ccb8bd5f9ccf444e4bda7713e3-Abstract.html): raster context and trajectory-bank latent nearest-neighbor distribution; a verified reusable public scoring implementation was not identified in this search. Replacing its bank by six dynamic HiVT candidates would remove a central part of the method. Not selected.
- [DenseTNT](https://openaccess.thecvf.com/content/ICCV2021/html/Gu_DenseTNT_End-to-End_Trajectory_Prediction_From_Dense_Goal_Sets_ICCV_2021_paper.html): dense-goal prediction/optimization changes candidate generation. Not a fixed-six post-hoc scorer.
- [Future-interaction-aware prediction via braid theory](https://github.com/caiocj1/traj-pred-braid-theory): auxiliary future-interaction supervision and predictor retraining, not an unchanged frozen-candidate ranking component. Outside this stage.
- Planning-oriented rule/reward rerankers optimize ego-driving compliance rather than human-agent mode selection; exclude them from this paper's prediction comparison.

## Feasibility verdict

Both actual public scoring components pass shape, probability-sum and finite-gradient checks with **zero optimizer updates**, using synthetic tensor-contract probes explicitly marked as such. Their code/source hashes and outputs are recorded in `02_literature/stage16_code_feasibility.json`. This is an engineering audit, not performance evidence. Neither supplies an immediately fair reproduced external baseline without a new registered adapter experiment. Prefer R-RNet's probability component for the lower-cost adapter; retain TNT as the better full-trajectory scoring alternative if detached context export is approved. No external paper metric is imported into our performance table.
