17. 核心 gradient 指标
============================================================

对于每个参数组计算：

cos_VP =

g_V · g_P
/
(||g_V|| * ||g_P|| + eps)

同时计算：

norm_V
norm_P

norm_ratio =
norm_V / (norm_P + eps)

记录：

dot product

============================================================
22. Effective gradient pressure proxy
============================================================

对每个 batch：

w_V =
vehicle valid supervised coordinates
/
(V+P+B valid coordinates)

w_P =
pedestrian valid supervised coordinates
/
total

然后计算描述性 proxy：

effective_V =
w_V * ||g_V||

effective_P =
w_P * ||g_P||

effective_ratio =
effective_V /
(effective_P + eps)

明确在报告中写：

这是 optimization-pressure proxy，
不是原始 mixed-loss 梯度的严格代数分解。

不能把它写成数学上完全等价的总梯度贡献。

34. 最终架构决策矩阵
============================================================

CASE 1：

Motion =
LOW_MOTION_DEGRADATION

且

GradientConflict =
SUPPORTED

推荐：

Dynamic Interaction Necessity-Gated Residual Adapter

即：

保留原 HiVT interaction 主路径：

h_base

额外关系分支：

Delta_h_rel

学习 gate：

g_i =
sigmoid(
MLP(
h_i,
type_i,
motion_i,
interaction_context_i
)
)

最终：

h_i' =
h_base
+
g_i * Delta_h_rel

重点：

moving / interaction-demanding actors
允许较高 gate

low-motion actors
允许接近0

--------------------------------------------------

CASE 2：

Motion =
UNIFORM_PEDESTRIAN_DEGRADATION

且

GradientConflict =
SUPPORTED

推荐：

Type-Decoupled Residual Interaction Adapter

即：

shared HiVT backbone 保留

relation residual
按 target type 使用独立小 adapter/gate：

Vehicle adapter
Pedestrian adapter
Bicycle adapter

避免 vehicle 优化方向
强迫 pedestrian 使用同一 residual mapping。

--------------------------------------------------

CASE 3：

Motion =
LOW_MOTION_DEGRADATION

但

GradientConflict =
NOT_SUPPORTED / WEAK

推荐：

Interaction Necessity Gate

但不引入复杂类别解耦。

重点根据：

motion magnitude
relative context
type

决定是否启用 interaction residual。
